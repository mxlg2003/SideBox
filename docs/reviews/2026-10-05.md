# Sidebox 三视角审查（2026-10-05）

只读审查，没有改产品代码，也没有启动应用逐项点过。结论来自文档和当前工作区源码（含未提交改动），界面行为是从 XAML / 文案 / 调用链推断的。

三份原始结论：

- 开发者：性能、正确性、可维护性
- 使用者：日常操作、信息是否好读、失败能不能恢复
- 产品：定位、功能是否成套、能不能按现在这样交付

仓库里更早的 `review_developer.md`、`review_user.md`、`review_product_manager.md`、`fix-plan.md`、`other-issues.md` 是上一轮审查。其中有些前提已经变了（例如情景开关、天气/日程是否存在、路径还指向 `H:\projects\WinDock`）。以本文为准。

## 总判断

现在的 Sidebox 是一块常驻边缘的模块岛：出厂只有时钟和便笺，设置首页是模块目录。文档里写的是按情境切换启动项的 Dock。

日常会绊到的是闹钟、便笺、情景切换和默认置顶。发布会绊到的是安装包，以及产品定义、模块目录、安装器各说各话。采样大体按「岛上有模块才启动」，快照会回到 UI 线程；模块上岛之后，GPU、磁盘、电源、进程的采样方式偏重。

## 高优先级

### 1. 定位承诺和出厂体验不是同一个产品

`docs/PRODUCT.md` 把产品定义成按当前情境切换一组启动项、信息和轻量动作，目标用户包括多显示器切换和 Windows 专注会话。同文件写明手动情景打开、自动触发关闭。这和 `ProductFeatures.ProfilesEnabled = true`、`AutoProfileTriggersEnabled = false` 一致。`ProfileEngine.Evaluate` 只在自动开关打开时才匹配专注、显示器和时间。

出厂 `general` 只钉时钟和便笺，`deep-work` 只钉专注计时器和便笺，并且带着一条永远不会触发的 Focus 规则（`DefaultProfiles.cs`）。`README.md` 一处写手动换情景默认关闭，另一处写默认打开。

按文档来的人会等「插上扩展坞 / 打开专注就换一套图标」。实际要到「高级 → 情景」手动切，两条出厂情景里都没有程序。深度工作这个名字会让人以为系统专注会接管 Dock。

### 2. 文档里的 MVP 和模块目录不是同一份清单

`docs/PRODUCT.md` 和 `docs/MVP-PLAN.md` 的模块表是时钟、便笺、系统状态、网络、电源、正在播放、Bing 壁纸、秒表、倒计时、闹钟、专注计时器、时间进度。天气和本地日历被标成不挡发布的 stretch。

`BuiltInWidgets.All` 另外包含 `weather`、`schedule`、`disk`、`gpu`、`processes`、`stocks`，`WidgetCatalog.Groups` 把它们放进系统、生活效率、商业。正在播放在文档里是正式模块，但 `NowPlayingEnabled = false`，`IsOffered` 会把它从目录和岛面上拿掉。`docs/DATA-MODEL.md` 的合法 widget id 仍停在旧的 12 个。`docs/PRODUCT.md` 仍把天气标成 stretch。`docs/DATA-MODEL.md` 写新安装 `autoHide=true`，`DefaultProfiles.CreateGeneral` 是 `AutoHide = false`，后者和 `docs/PRODUCT.md`「默认不自动隐藏」一致。

按 MVP 验收会漏掉用户已经能添加的六个模块，同时验收一项用户根本看不到的「正在播放」。时间类就有时钟、秒表、倒计时、闹钟、专注计时器、时间进度，日程里还有另一套倒数。

`docs/ARCHITECTURE.md` 禁止 `WinDock.App` 出现 `DllImport`，`NativeTrayIcon.cs` 直接 P/Invoke。`DockSession`、`DockWindow`、`ScheduleWidget` 都在两千行以上。测试覆盖了进程表能看到当前进程，以及 GPU 通配计数器能读到一个数；没有覆盖媒体回退频率、多实例 `SetOptions`、闹钟跨情景唤起。

### 3. 安装包还不能当成面向普通用户的 1.0

`pack/publish.ps1` 使用 `--self-contained false`。`pack/WinDock.iss` 版本号 `1.0.0`、发布者 Sidebox，没有最低系统版本，没有运行时检测；开机启动任务文案写死，向导语言包含英文。`app.manifest` 的程序集版本是 `0.1.0.0`，`supportedOS` 用的是 Windows 10 兼容 GUID。文档要求的下限是 Windows 11 22H2。签名留到有证书之后。`README.md` 把「本机已有 Windows Desktop Runtime」写成开发前提。

没有 .NET 10 桌面运行时的机器装完打不开。Windows 10 装得上，但不是支持范围。未签名安装包会被 SmartScreen 拦住。关于页和安装器版本对不上。

### 4. 闹钟、倒计时、专注计时器冷启动不会在后台响

文案承诺到达预设时间发出提示音与系统通知（`UiText`）。实际是系统提示音加托盘气球（`AlarmWidget`）。`AlarmEngine.Tick` 只在 `AlarmWidget` 的 1 秒 `DispatcherTimer` 里调用。只有当前情景的 `dock.items` 会进 `GetOrCreateWidget`。`IKeepAliveWhileRunning` 只保住已经创建且仍武装的实例。逾期超过 36 小时，`Alarm.WithResolvedRing` 会静默解除，岛上也不解释错过了。倒计时和专注计时器是同一模式。开机启动在「关于」里，默认不写注册表（`RunAtStartup`）。

闹钟设在「日常」、重启后停在「深度工作」，到点没有声音也没有通知。同一次运行里，先打开过该情景再切走，计时器还能继续。超过 36 小时再切回去，闹钟直接被清掉。

### 5. 「隐藏便笺」要么直接删掉，要么藏到很难找的地方

右键便笺只有「隐藏便笺」（`DockContextMenuBuilder`）。空白便笺会 `RemoveDockItem` 并删文件；写过字的才 `HideDockItem`（`DockSession`）。历史只画在便笺自定义页（`NotesWidget`）。恢复会换掉当前这张，提示是「替换当前便笺」，不是「放回 Dock」。正文里的删除有确认，历史垃圾桶没有。

### 6. 「关闭所有窗口」没有确认

程序开了多个窗口时，右键菜单里点一次「关闭所有窗口」，会逐个发送 `WM_CLOSE`（`DockContextMenuBuilder`、`Win32WindowSwitch`）。单个窗口的菜单里没有这项。浏览器、编辑器可能直接关掉。

### 7. 情景一点就换掉整条 Dock，而且没有提示

岛上右键后半段直接是「日常」「深度工作」，没有「情景」标题（`DockContextMenuBuilder`）。`SwitchProfile` 只提交切换，不发通知。全局热键默认是 `Win+Shift+D`（下一个）和 `Win+Shift+Z`（撤销），设置写明暂不支持自定义。Dock 菜单里没有撤销，撤销在托盘或「高级 → 情景」。

出厂就有一个叫「深度工作」的情景，触发器是 `TriggerType.Focus`。自动触发总开关为 false，引擎在匹配之前就返回。设置里的说明只讲专注计时器是本地番茄钟，不会自动切情景，没讲这个情景自己的专注触发也是关的。

### 8. 默认岛会盖住窗口；收起来之后又很难叫出来

第一次打开是屏幕上沿居中的置顶岛，`AutoHide = false`（`DefaultProfiles.CreateGeneral`）。产品说明写明 AppBar 预留还没产品化，靠自动隐藏避开标题栏。最大化窗口的标题会被挡住。

打开自动隐藏后，岛缩成大约 4 像素的边（`DockTokens`），鼠标要碰到大约 8 像素的热区才滑出（`DockHostGeometry`）。`RevealHotkey` 默认 false，所以这时 `Win+Shift+A` 没用。布局说明只讲边缘会显示翻页箭头，没写热区有多窄。

### 9. 股票被当成正式模块

产品文档和 MVP 计划都没有股票。目录文案是「盯一只股票的现价、分时和涨跌」。行情来自 `push2.eastmoney.com` / `search-codetable.eastmoney.com`，默认约 20 秒拉一次，失败时留下上次成功的报价（`StockProvider`）。涨跌色在 `DockTokens` 写明是绿涨红跌，板块文案却是科创、创业、北证。分时图写「历史采样 · 每 5 分钟」，没有「延迟 / 非官方 / 非投资建议」。

接口一变就空，失败时继续显示旧价，A 股用户会把红绿读反。它和「钉程序、看本机状态」没有同一件事，却和时钟一样出现在添加列表里。

## 性能

系统采样按当前岛上的模块 `Start` / `Stop`，`--safe` 会全部停下。进程列表还要 `privacy.processNames`。快照经 `UiPump.Coalesce` 用 `BeginInvoke` 回到 UI 线程，采样线程不直接改控件。这些路径本身合理。下面是模块上岛之后的成本。

### 10. GPU 每 2 秒做一次全引擎查询，并新建 DXGI 工厂

`GpuSampler` 默认周期 2 秒，自动隐藏时 10 秒。每次 `Capture` 都 `DxgiAdapters.TryRead()`，里面 `CreateDXGIFactory` 并枚举适配器。利用率来自 `GpuEngineQuery` 的 `\GPU Engine(*)\Utilization Percentage`，再在托管代码里逐实例扫名字。独显加进程多时，通配计数器实例数会到数百。异常路径上工厂的 `ReleaseComObject` 可能漏掉。具体毫秒数没有在这台机器上实测。

### 11. 磁盘每 2 秒对可移动盘调用 `IsReady`

`DiskSampler` 周期 2 秒，安静时 10 秒。`ReadVolumes` 对每个 Fixed / Removable 盘调用 `drive.IsReady`，再读容量。`DiskWidget.ApplySettings` 把活动计数器固定成关闭，`PhysicalDisk` 那条目前不会开。空读卡器上 `IsReady` 可以卡住线程池线程数秒，磁盘卡片停止更新。UI 线程本身不直接调用它。这次没有插空读卡器复现。

### 12. 电源轮询偏勤，岛宽又不跟着设备数变

`Win32PowerProvider.Pulse` 每次都 `PnpBluetoothBatteries.Read()`，对 `BTHENUM` / `BTHLE` / `BTHHFENUM` 做 `SetupDi` 扫描。空闲 15 秒，蓝牙变化后 400ms 爆发 12 秒。`SameReading` 把剩余秒数和充电毫瓦算进相等性。`PowerWidget.Render` 每次都 `Children.Clear()` 再新建单元格。`IslandLayoutChanged` 只在从隐藏恢复时发出，窗口尺寸来自上次 `MeasureIsland`。

电池剩余时间或功率一变就在 UI 线程拆掉重建设备条。第二只耳机出现后，自适应岛宽要等别的布局事件才会变。400ms 时功率抖动有多频繁，没有实测。

### 13. 进程列表每次为全部进程分配行，图标缓存只增不减

`ProcessListSampler.Capture` 每拍 `SystemProcessTable.ReadRecent()`，为每个进程建行，再按 CPU 和内存各排一次，只展示前 5+5。弹出层打开时 2 秒，否则 5 秒，安静时 10 秒。对大约 10 个进程 `OpenProcess` + `QueryFullProcessImageName`，缓存未命中则 `Icon.ExtractAssociatedIcon` 写 PNG（`ProcessIconCache`）。钉选圆点另有 3 秒一次的运行中映像路径查询，和进程表共用 1.5 秒缓存。隐私关时不会 `Start`。

进程模块在岛上时，每几秒分配一整张进程表。图标目录按 exe 路径一直增长。`ExtractAssociatedIcon` 在进程内加载图标，失败被 `catch` 吃掉，但访问违例不一定能被接住。

### 23. 「正在播放」的每秒扫描是潜伏成本

`GsmtcMediaProvider.TickAsync` 每秒调用 `MediaTransportFallback.TrySnapshot`。后者对 `KnownLocalPlayers.All` 的 9 个进程名各做一次 `Process.GetProcessesByName`；某个播放器在跑时再扫一遍，并对窗口 `EnumWindows` + `GetWindowText`。GSMTC 已有会话时这条路径仍会走。

`DockSession` 只在当前岛的 id 里包含正在播放时才 `Hub.Media.Start`。`NowPlayingEnabled = false`，`ProfileEngine` 按 `IsOffered` 过滤，目录和岛面都不会放上这块模块。今天的出厂用户不会付这个成本。开关一打开，或旧配置绕过过滤，它就是当前最重的常驻扫描。

## 功能、信任与信息

### 14. 多份同类模块共用一个采样器

`ProviderHub` 各持有一个 `GpuSampler`、`PerformanceCounterSampler`、`Win32PowerProvider`。每个控件在加载和 `ApplySettings` 里调用 `SetOptions`：GPU 的适配器和引擎、系统状态的逐核和频率、电源的功率和健康度。按岛上顺序逐个再设一遍。

产品允许同一模块多份。两块 GPU 卡片会显示同一张卡。一块系统状态关掉「逐核」后，另一块的核图也空。未指定 GPU 适配器时用枚举结果的第一块（`GpuSampler.Pick`），笔记本上经常不是独显。读不到引擎时占用显示为「—」。

### 15. QUNS 成功时仍用 97% 窗口启发式判定全屏

`UserNotificationState.EvaluatePresentationOrFullscreen` 只在 `SHQueryUserNotificationState` 返回 D3D 全屏或演示时直接成立。返回成功但不是这两种状态时，仍调用 `IsForegroundCoveringMonitor`。非最大化且宽高达到显示器 97% 时，岛会避让。`docs/ARCHITECTURE.md` 写的是：QUNS 成功且不是这两种状态时不再用该启发式。宿主脉冲在自动隐藏悬停时是 100ms，结果有 400ms 缓存。

几乎铺满屏幕、但不是最大化、QUNS 也没报全屏的窗口，会把 Dock 收成隐藏或避让。

### 16. 系统监视器叠在一起，进程名会一直亮在岛上

目录「系统」同时有系统状态（CPU + 内存）、网络、电源、磁盘、GPU、进程。系统状态、GPU、磁盘上岛后约 2 秒采一次。进程在展开时 2 秒、平时 5 秒、岛隐藏时 10 秒，先枚举再只显示前 5 名。枚举走 `NtQuerySystemInformation`。`docs/PRODUCT.md` 要求未文档化手段只能做实验开关并自动回退。`docs/DATA-MODEL.md` 仍把 `processNames` 写成预留，CPU 模块不列进程。

实现里进程是正式模块。第一次添加会征求同意（`DockSession.TryConsentForWidget`，`UiText.ConsentProcesses`）。同意之后，占用最高的进程名直接写在 Dock 上（`ProcessWidget` 使用 `top.Name`），旁边的人也能看见。关掉隐私后模块还在，岛上变成「已关闭」。

默认不上岛是对的。目录把它做成一等功能，就把采样成本和隐私面交给了每个好奇的人。Windows 更新后这条未文档化接口可能直接失效。

### 17. 天气文案比数据来源更满

简介写「实时天气，支持自动定位」。实现是 Open-Meteo 预报，约 30 分钟刷新（`WeatherProvider`）。自动定位请求 `https://get.geojs.io/v1/ip/geo.json`。同意文案写默认只用填写的城市，定位是 HTTPS 查询大致城市，没有写出 geojs.io，也没有写这是按 IP 估的城市。城市搜索写死 `language=zh`。`docs/DATA-MODEL.md` 仍把 `preciseLocation` 标成天气 stretch。

添加天气会先同意访问 Open-Meteo，但不会替用户选城市。岛上是 `--°`，状态是「选择城市」或「天气暂时不可用」。网络失败和「还没设城市」挤在同一小条状态上。离线缓存会标「离线缓存」。紧凑状态没有最大宽度或省略。

用户会以为是本机实时天气。IP 城市会偏。英文界面搜城市可能返回中文名。第三方能看到出口 IP。同意流程比简介诚实。

### 18. 「日程」看起来像日历，实际是本机手写清单

简介是「今日工作生活待办日程与重要纪念日/倒数日」。`Schedule` 是本地事件和倒数，仓库里没有系统日历读取。中文按钮是「分类…」，英文是 “Calendars…”。`docs/PRODUCT.md` 要求系统日历在无包身份时降级，禁止假装已同步 Outlook。`docs/MVP-PLAN.md` 把本地日历放在 stretch。

英文用户会去找 Outlook 或 Windows 日历里的今天。打开之后是空的自建分类。这和倒计时、闹钟抢同一件事。

### 19. 不支持 GPU 计数时，岛上只有一个横杠

`GpuWidget` 在不支持时主值是「—」。说明文字「此电脑不支持 GPU 计数器」只在点开的面板里。看起来像还在加载，或数据坏了。

### 20. 磁盘在岛上把所有盘加总成一个数

`Disk` 把可见卷的容量相加后再格式化。岛上一个「xx GB」或一个百分比，看不出是 C 盘还是几块盘加在一起。没有盘时是「—」。各盘明细要打开面板。

### 21. 设置结构把核心任务放到了边上

设置导航第一组是「模块」，然后布局、外观、隐私、关于；情景在「高级」里（`SettingsWindow.xaml`）。钉程序的文案在 Dock 右键和拖入。出厂岛已经有时钟和便笺，空 Dock 那句引导不会出现。情景热键写明暂不支持自定义。唤醒热键可以录制。布局页另有「程序折叠」「文件夹折叠」。

第一次打开设置，产品在请用户加模块，不是请用户钉每天要开的程序。`Win+Shift+D` 被占用时，用户改不了切换键，只能改唤醒键。

右键程序点「从 Dock 移除」立刻消失，不能撤销（`DockContextMenuBuilder`）。模块除日程外同样直接移除。日程会问一句，并说明数据还在。

Tab 到岛上时，程序图标可以用 Enter 或空格打开。时钟、便笺、天气这些模块槽没有设成可聚焦（`DockWindow` 只给程序和折叠堆设了 `Focusable`）。各模块 `Popup.StaysOpen = false`。便笺在关闭时保存，字不一定丢，但正在改的闹钟或日程会突然收起。键盘这条是代码推断，没有在运行的窗口里按过。

### 22. 配置版本、品牌和损坏恢复还没形成可升级的产品

`SettingsSchema.CurrentVersion = 1`。`docs/DATA-MODEL.md` 写 v1 无历史迁移。更高 schema 不覆盖文件，内存改用出厂默认（`JsonSettingsStore`，文案 `UiText.NewerSchema`）。读坏了会改名损坏文件并写出厂配置。旧目录 `%AppData%\WinDock` 只在 Sidebox 目录还不存在时整目录搬走。用户可见名称是 Sidebox（`ProductInfo.Name`），图标文件仍是 `WinDock.ico`，自启旧值名是 `WinDock`。

已经装过 WinDock 的人，如果 Sidebox 目录先被建出来，旧配置不会跟过来。设置损坏会回到时钟和便笺，钉过的程序没了。schema 还停在 1，后面一旦加版本，旧构建会整份退回出厂而不是迁移。

## 低优先级

### 24. 台式机上的电源模块，不悬停看不出意思

没有电池时，岛上是一枚空电池图标，说明「未检测到本机电池」只在悬停提示里（`PowerWidget`、`PowerDevices`）。有电池但设备被全部隐藏时，岛上是一整句「未检测到电池或已连接的蓝牙设备」或「已全部隐藏」，容易把岛撑得很宽。这条没有在台式机上点过，置信度中等。

## 查过、认为没有问题的路径

边界守住了。不替换任务栏，默认 `asInvoker`，AppBar 不进设置，自动情景默认关闭。专注计时器的文案写明它不会触发 Windows 专注，也不会切情景。正在播放是整模块下架，不是一张会读错歌名的卡片。

隐私和采样的默认值合理。权限默认关。网络、进程、Bing、天气在第一次添加时征求同意。采样跟着模块上岛才 `Start`。出厂只有本地时钟和便笺。开机启动在安装任务里默认不勾。卸载删 Run 键并保留 `%AppData%\Sidebox`。`--safe` 能回到只有 Overlay、没有模块的 Dock。

Bing 壁纸把副作用说清楚了。添加时说明会访问 bing.com，设成桌面壁纸时再确认一次，失败和恢复上一张壁纸都有用户可见的句子。

怎么进设置、怎么加模块，说得明白。空岛写着右键添加程序，添加模块请打开设置。托盘左键和 Dock 右键都能开设置。设置默认停在「模块」页。关掉设置窗口只是隐藏，并会提示程序还在边缘运行。重复钉选会告诉你「已在 Dock 上」。删情景、删便笺正文、移除日程都有确认。网络速率带 KB/s、MB/s。

便笺 `Sweep` 用的是所有情景里（含隐藏便笺）的 id。设置写入是临时文件、`Flush(true)`、再替换。`networkDetails=false` 时会关掉适配器枚举，采样器只问是否联通。x64 进程表字段偏移与当前 `SYSTEM_PROCESS_INFORMATION` 布局一致，并且有「能看到当前进程、工作集数量级正确」的测试。这次没有跑测试，也没有在本机插拔设备验证磁盘和蓝牙。
