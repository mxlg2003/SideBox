# 其余问题汇总

> 与 [fix-plan.md](fix-plan.md) 配套。本文收录：**不合理或证据不足**、**需产品拍板**、**超出 MVP / 明确不做**、**过大不适合当缺陷修**、以及 **可修但优先级低** 的条目。  
> 不表示这些问题永远不做，只表示 **现在不应塞进修复批次**。

审查原文共约 87 条（开发者 30 + 使用者 34 + 产品经理 23），去重后约 50 个独立问题。其中 **约 30 条** 已收入修复方案；其余按类如下。

---

## 1. 需产品拍板，不是代码缺陷

这些描述大多属实，但「怎么改」取决于 WinDock 要当什么产品。在 `ProductFeatures` 和 `docs/PRODUCT.md` 改口之前，不要当 bug 修。

| 来源 | 主张 | 为何不进修复方案 | 若要推进 |
|---|---|---|---|
| P-03 | 情景整体关闭，一句话定位落空 | 这是有意的开关（`ProfilesEnabled = false`），不是实现漏了。打开后还缺规则编辑器，那是功能范围 | 二选一：交付手动情景 + 至少一种自动触发；或改定位/README/关于页，承认当前是边缘信息岛 |
| P-09 | stretch 的天气/日程/闹钟抢在情景之前做完 | 范围治理，不是运行时错误。天气/日程的 **隐私和丢数据** 已在修复方案 | 冻结新模块是流程决定；质量问题走 fix-plan A4/A5/C1 |
| P-14 | 计时类模块与 Win11 时钟重叠，应合并 | 产品组合意见。合并秒表/倒计时/闹钟是一次交互重做 | 发布后再评估；当前先保证移除/持久化正确（fix-plan B4） |
| P-10 默认顶边 + 自动隐藏削弱「一眼看到」 | 与 PRODUCT 默认布局一致 | 改默认边缘或首启强制不隐藏，要改出厂配置 | 首启误报已在 A2；「第一次保持可见」可列为产品实验，不强制 |
| U-26 | 顶边会挡浏览器标签，热区应加停留门槛 | 设计取舍。U-01 修好后误触会变明显，但是否改默认边是产品问题 | 热区 150–300ms 停留可作为小实验，不进必须批次 |
| P-17 | 情景引擎做好了却藏着，维护成本高 | 投入产出判断。引擎和测试已存在，删掉更危险 | 改成运行时实验开关可以另开任务，不是修缺陷 |
| P-15 | 退出入口有 6 处，矫枉过正 | 上轮「找不到退出」已修。减入口是 UX 口味 | 可留托盘 + 岛空白右键 + 设置三处；不要当 P0 |
| P-21 | 卸载保留用户数据、没有「同时删除」 | 与 MVP-PLAN「保留 AppData」一致 | 安装器加可选删除；隐私向增强，非缺陷 |

**建议：** 发布说明里用一段话写清「当前版本情景为实验/关闭，默认是顶边自动隐藏的信息岛」，避免文档仍写「情境化桌面控制面」。文案同步属于 fix-plan C9 的延伸，但 **要不要做情景** 必须先拍板。

## 3. 过大的技术债（承认，但不当本轮缺陷）

这些观察基本正确，拆开做才有意义。塞进「修复方案」会变成无边界重构。

| 来源 | 问题 | 说明 |
|---|---|---|
| D-21、上轮开发者 | `DockSession` / `DockWindow` / `WidgetViews` 上帝类 | 仍在胀。抽出菜单和显示器枚举只是开了头。应在功能稳定后按职责切，不要为切而切 |
| D-20 | Token 三份拷贝（`DockTokens` / `DockLayoutConstants` / `DockVisualTheme`） | `DockVisualTheme` 零引用，**删掉未使用副本** 其实很小，可并进一次 UI 清理。整套「Core 不准有颜色」是架构洁癖，Core 继续给 WPF 宿主用可以接受 |
| D-19 | App 层 `DllImport`（托盘） | 规则被破了。托盘迁到 Shell **可以做**，但应和 B2 托盘重建一起做；单独搬文件不增加用户价值 |
| D-28 | Shell / Providers / Widgets 几乎没有逻辑测试 | 同意。优先给 fix-plan 里的纯函数补测（Sweep、日程 Normalize、天气 HTTP、自动隐藏时钟），不要先追求「给 DockWindow 写 UI 测试」 |
| D-12 | 混合 DPI 下 DIP 赋给 `Window.Left` | 置信度中低，需 150%+100% 双屏实机。有证据再单开任务，不要按推测改坐标栈 |
| U-25 全部 | 键盘 / 读屏 / 高对比度 | 模块按钮大量是 `Border`+鼠标事件，补齐是横向工程。修复方案只收了快捷键框吞 Tab。其余进无障碍专项 |
| U-31 | 云母/磨砂/玻璃名不副实、无滑出动画、高 DPI 图标虚 | 已知限制（PRODUCT 已写图标按 48px）。真亚克力与动画是视觉专项 |
| D-29 | 嵌入 8.3MB 中文字体 | 为文件夹角标。可改系统字体或子集化，收益是内存，需实测 80MB 预算后再做 |
| 计时模块不持久化运行态 | U-13 | 闹钟已持久化；倒计时/秒表/专注只在内存。要不要「重启后继续倒计时」是产品问题，修法不复杂但要定义休眠、改系统时间后的行为。放入其他，不进必须批次 |

## 5. 低置信 / 必须实机后才能当缺陷

代码看起来像问题，但用户是否真遇到，要以实机为准。确认后再从本文挪到修复方案。

| 来源 | 内容 | 怎么验证 |
|---|---|---|
| D-07 | Alt+F4 关掉 Dock 岛 | 焦点在岛/便笺时按 Alt+F4，看岛是否消失、托盘是否还在 |
| U-10 | 多窗口轮换因 Dock 抢前台而失灵 | 开 3 个记事本连点钉选。若能轮换，B3 可降级为仅 NOACTIVATE 防抢焦点 |
| D-12 | 混合 DPI 窗口位置偏移 | 笔记本 150% + 外接 100%，把 Dock 指定到副屏 |
| D-11 | 封面文件并发写导致空白/旧图 | 连续切歌观察封面 |
| D-18 | 离线 SMB 钉选卡住 UI | 钉一个不可达 `\\server\share\app.exe` 再点 |
| U-15 | 勿扰/专注模式下托盘气球被吞 | 开 Focus 后等闹钟。若不可接受，要改用持续响铃 UI 而不是系统气球（工作量中等） |

## 8. 建议的决策清单（给产品，不是给实现）

发布前只需要回答这四句，其余保持「明确不做 / 延后」：

1. **情景：** 本版本对外怎么讲？关闭并改文案，还是最小交付手动切换？
2. **天气：** 修完隐私后保留，还是标实验/移出 v1？
3. **日程：** 保留并修好丢失，还是降级为「今日备注」并去掉 100 条静默丢弃？
4. **默认自动隐藏：** 逻辑修对之后，新用户是否仍默认隐藏？

这四句一旦写下，fix-plan 的 A/B 批次不需要再等。
